   423→# 6. MOTION AND INTERACTION SYSTEM
   424→
   425→Motion is a core part of the design, but it must be disciplined.
   426→
   427→## 6.1 Motion hierarchy
   428→
   429→Create five levels:
   430→
   431→### Level 1 — Instant feedback
   432→For taps, clicks, buttons, toggles, and focus states.
   433→
   434→- 80–160ms
   435→- Immediate
   436→- No input delay
   437→
   438→### Level 2 — Microinteraction
   439→For links, thumbnails, labels, cursor states, and small UI changes.
   440→
   441→- 160–300ms
   442→- Precise
   443→- Subtle
   444→
   445→### Level 3 — Component reveal
   446→For headings, images, captions, and project metadata.
   447→
   448→- 400–800ms
   449→- Choreographed
   450→- Never all at once
   451→
   452→### Level 4 — Section transition
   453→For changes between project worlds and major narrative chapters.
   454→
   455→- 700–1400ms
   456→- Cinematic but controlled
   457→- Must preserve scroll clarity
   458→
   459→### Level 5 — Signature moment
   460→For one or two unforgettable 3D/WebGL scenes.
   461→
   462→- 1200–2600ms
   463→- Meaningful
   464→- Performance-aware
   465→- Never repeated everywhere
   466→
   467→## 6.2 Motion principles
   468→
   469→- Motion must reveal relationships.
   470→- Motion must communicate direction.
   471→- The visitor should understand what caused an animation.
   472→- Keep stillness between intense sections.
   473→- Do not blur every text reveal.
   474→- Do not split every word into letters.
   475→- Do not use spring motion for everything.
   476→- Do not make content chase the cursor.
   477→- Do not delay navigation for visual drama.
   478→- Do not scroll-jack basic reading.
   479→- Do not make the visitor scrub through an unnecessarily long pinned timeline.
   480→- Avoid multiple animation libraries fighting over the same transforms.
   481→- Stop hidden animation loops.
   482→- Pause WebGL when offscreen.
   483→- Respect reduced motion completely.
   484→
   485→## 6.3 Cursor behavior
   486→
   487→Desktop fine-pointer devices only.
   488→
   489→The cursor may:
   490→
   491→- Reveal project labels
   492→- Slightly distort selected media
   493→- Pull a button by a few pixels
   494→- Scrub a short preview
   495→- Activate a subtle 3D response
   496→- Change context between “View,” “Drag,” “Open,” and “Explore”
   497→
   498→Rules:
   499→
   500→- Keep click precision
   501→- Never hide the native cursor on text fields
   502→- No large blob covering content
   503→- No lag
   504→- No cursor effect on touch devices
   505→- No essential information on hover only
   506→
   507→## 6.4 Scroll behavior
   508→
   509→Use smooth scrolling only when it improves the experience.
   510→
   511→- Normal wheel and trackpad input must remain responsive
   512→- Scroll must never feel delayed or heavy
   513→- Anchors must work
   514→- Browser back must work
   515→- Pinned scenes must release correctly
   516→- Mobile should use shorter, more direct sequences
   517→- Avoid long horizontal-scroll traps
   518→- Restore scroll position appropriately after returning from a case study
