# 6. MOTION AND INTERACTION SYSTEM

Motion is a core part of the design, but it must be disciplined.

## 6.1 Motion hierarchy

Create five levels:

### Level 1 — Instant feedback
For taps, clicks, buttons, toggles, and focus states.

- 80–160ms
- Immediate
- No input delay

### Level 2 — Microinteraction
For links, thumbnails, labels, cursor states, and small UI changes.

- 160–300ms
- Precise
- Subtle

### Level 3 — Component reveal
For headings, images, captions, and project metadata.

- 400–800ms
- Choreographed
- Never all at once

### Level 4 — Section transition
For changes between project worlds and major narrative chapters.

- 700–1400ms
- Cinematic but controlled
- Must preserve scroll clarity

### Level 5 — Signature moment
For one or two unforgettable 3D/WebGL scenes.

- 1200–2600ms
- Meaningful
- Performance-aware
- Never repeated everywhere

## 6.2 Motion principles

- Motion must reveal relationships.
- Motion must communicate direction.
- The visitor should understand what caused an animation.
- Keep stillness between intense sections.
- Do not blur every text reveal.
- Do not split every word into letters.
- Do not use spring motion for everything.
- Do not make content chase the cursor.
- Do not delay navigation for visual drama.
- Do not scroll-jack basic reading.
- Do not make the visitor scrub through an unnecessarily long pinned timeline.
- Avoid multiple animation libraries fighting over the same transforms.
- Stop hidden animation loops.
- Pause WebGL when offscreen.
- Respect reduced motion completely.

## 6.3 Cursor behavior

Desktop fine-pointer devices only.

The cursor may:

- Reveal project labels
- Slightly distort selected media
- Pull a button by a few pixels
- Scrub a short preview
- Activate a subtle 3D response
- Change context between “View,” “Drag,” “Open,” and “Explore”

Rules:

- Keep click precision
- Never hide the native cursor on text fields
- No large blob covering content
- No lag
- No cursor effect on touch devices
- No essential information on hover only

## 6.4 Scroll behavior

Use smooth scrolling only when it improves the experience.

- Normal wheel and trackpad input must remain responsive
- Scroll must never feel delayed or heavy
- Anchors must work
- Browser back must work
- Pinned scenes must release correctly
- Mobile should use shorter, more direct sequences
- Avoid long horizontal-scroll traps
- Restore scroll position appropriately after returning from a case study
